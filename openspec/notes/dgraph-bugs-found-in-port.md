# Dgraph bugs found while porting

The port reproduces Dgraph's behaviour, bugs included, unless a spec declares a behaviour change; step 3 of the plan
(`dgraph-port-overview.md`) fixes known bugs on the tested Rust code. This ledger holds what the port found, with the
evidence, so step 3 starts from it. Paths are in the Dgraph fork at commit `9fbf35614` (v25.5.0). The remedies, and the
port's behaviour once they land, are the OpenSpec change `fix-ported-dgraph-defects`.

| # | Where | What happens | Called in production | The port |
|---|---|---|---|---|
| 1 | `algo/packed.go`, `IntersectSortedPacked` | The loop assigns to a shadowed `out` (`out := IntersectWithLinPacked(out, ls[i].l)`), so the result is the intersection of the two shortest lists only; with three lists where the third shares less, it returns `[2,3,9]` where the answer is `[9]` | No; tests only | Reproduces it |
| 2 | `algo/packed.go`, `DifferencePacked` | Once the last block of `v` is exhausted, it stops after `u`'s current block and drops the remaining UIDs of `u`: `2..15` minus a shorter `v` returns `2..10` | No; tests only | Reproduces it |
| 3 | `algo/uidlist.go`, `IntersectCompressedWith` | Panics with an index out of range when `afterUID` lies past the pack's last UID and the binary strategy is chosen: `SeekToBlock` indexes `Blocks[len(Blocks)]` (`codec/codec.go:230`) | Yes, from a client: DQL's `after:` reaches it on a filtered read of a rolled-up list, and no `recover()` exists in `worker`, `query`, `edgraph` or `posting`, so the Alpha process ends | Reproduces the panic |
| 4 | `codec/codec.go`, `Decoder.SeekToBlock` | Panics at `:264` on a decoder never sought when the target lies in the first block, and on a sought decoder holding a corrupt block with `NumUids = 0` | No production caller hands it an unsought decoder; a corrupt `UidPack` from disk or another node reaches it | Reproduces the panic |
| 5 | `codec/codec.go`, `Decoder.LinearSeek` | Never returns for a target of `math.MaxUint64`: `PeekNextBase` returns `MaxUint64` past the last block, a sentinel equal to that target. No covering or token differed in the vectors tested | Yes | Computes without fusing, as amd64 Go does; golden vectors are generated with fusing off (`scripts/golden.sh`) |
| 12 | `dql/parser.go` | Parse outcomes depend on Go's map iteration order: of 2,346 golden inputs generated 41 times, 293 gave different outcomes between runs (which error is reported, or which of several failing arguments is named) | Yes | Deterministic: arguments sit in an ordered map, so the same input always reports the same error |
| 13 | `dql/mutation.go`, N-Quad conversion | `ToDeletePredEdge` with subject `*` and no object value, and a direct `CreateValueEdge` without a value, dereference nil and panic; `ToEdgeUsing` refuses such an N-Quad with `Unknown value type for nquad` | No: DropAttr sets the value and the bulk mapper checks it first | Treats the missing value as an empty string |
